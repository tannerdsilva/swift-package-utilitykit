# Installation

## Prerequisites

- Swift 6.0+ toolchain (macOS 13+)
- Xcode 16+ (recommended) or standalone Swift toolchain

## From source

```bash
git clone git@github.com:tannerdsilva/swift-package-utilitykit.git
cd swift-package-utilitykit
swift build -c release
cp .build/release/swift-package-tool ~/.local/bin/
```

## Via Makefile

```bash
make install-plugin
```

This builds the release binary, installs it to `~/.local/bin`, and writes
the generated harness plugin manifest into `~/.arc/plugins`.  (`~/.local/bin`
is the canonical install location — harness resolvers fall back to it, so the
installer and the manifest agree.  Override with
`PREFIX=`/`BIN_DIR=`/`PLUGINS_DIR=`.)

## Via install subcommand

The `swift-package-tool` binary owns install/remove logic natively
(`install`, `uninstall`, `path-wire`) and is harness-agnostic:

```bash
swift-package-tool install --no-build                    # binaries only (no adapter)
swift-package-tool install --plugins-dir ~/.arc/plugins  # + generated manifest
swift-package-tool uninstall --plugins-dir ~/.arc/plugins # remove binaries + manifest
```

`PATH_UPDATE`/`NO_INTERACTIVE` are honored as environment overrides.  the
adapter step writes the manifest generated by the *installed* binary
(`plugin --mcp-manifest arc`), and runs only when a plugins dir is given
(`--plugins-dir` or `PLUGINS_DIR`); with none, the installer manages the
binaries and PATH wiring alone.  native MCP clients need no files at all:
register `swift-package-tool plugin` as a stdio server (`hermes mcp add`).
